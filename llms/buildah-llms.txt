# Buildah

> Buildah is an Apache-2.0 command line tool for building OCI-compliant container images
> without a container runtime daemon and without root privileges. It is part of the CNCF
> Podman Container Tools project. Buildah has no hosted API, no SaaS surface and no
> accounts: the CLI and the Go library `go.podman.io/buildah` are the entire interface.

Important for agents: there is nothing here to call over HTTP. Buildah runs locally. An
agent works with Buildah by executing `buildah` subcommands on a Linux host, or by
importing the Go module. Anything that claims to be a hosted Buildah API is not from this
project.

Latest release: v1.45.0 (2026-07-30).

out of the `containers` GitHub organization in 2026; `github.com/containers/buildah`

## Command reference

- [buildah(1)](https://github.com/podman-container-tools/buildah/blob/main/docs/buildah.1.md): global flags and the full command table.
- [All man pages](https://github.com/podman-container-tools/buildah/tree/main/docs): one markdown man page per command.

Core commands: `build` (build from a Containerfile or Dockerfile), `from` (create a working
container), `run` (run a command inside it), `copy` / `add` (put files in it), `config`
(set image configuration), `commit` (turn it into an image), `push` / `pull` (move images
to and from OCI registries), `login` / `logout` (registry credentials), `manifest` (multi
architecture image indexes), `source` (source images and artifacts), `mount` / `umount`,
`images`, `containers`, `inspect`, `tag`, `rename`, `rm`, `rmi`, `prune`, `mkcw`,
`unshare`, `info`, `version`.

## Standards

Buildah's default output format is OCI image-spec v1.0. It reads and writes the OCI image
layout, pushes and pulls against OCI Distribution Spec registries, builds OCI image
indexes, and delegates `RUN` to an OCI runtime. Docker manifest v2s2/v2s1 output is
available with `--format docker`. Detail: `conformance/buildah-conformance.yml` in this
profile.
